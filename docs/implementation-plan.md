## 产品范围
- 产品名统一为 TigerType，crate 使用 `tigertype-*`、程序为 `tigertype.exe`，工作区目录为 `TigerType`，正式数据目录为 `%APPDATA%\TigerType`。窗口、IPC 管道/帧标识及目录所有权标记同步使用新名称；开发期不兼容旧名称的程序或受管目录，不迁移或改写已有数据。
- Windows 10/11 x64、x86 宿主，含管理员和 UWP/AppContainer（沉浸式）宿主；Rust 专用单字引擎，不兼容 Rime。LPAC 宿主、UILess 模式和触摸键盘避让暂不支持；连不上后台时放行原键。
- 单字码表按权重降序、原始行序稳定排序；无词组、调频、造词。
- 默认四码待选、下一码顶屏；可开启四码唯一自动上屏，唯一性在过滤/转换/去重后判定。
- 空格选字、数字选重、分号次选、引号三选、翻页、退格、清屏、中英文切换；空码不误上屏；满四码空码时下一码顶上清屏（同小狼毫 `auto_clear: max_length`），无对应候选的选重、越界翻页等静默忽略，不弹文字提示（主流输入法均不弹）。
- 普通输入默认常用字集，可切全字集；查字始终全字集。普通输入默认隐藏学习信息，可临时显示。
- 反引号单字拼音反查：无调全拼、ü/v、多音字、可选字上屏；无双拼、整词、整句、模糊纠错。
- 独立查字窗输入拼音/粘贴汉字，显示可用编码、完整编码、读音、拆分；多字逐字展示，不造词。复制由用户点击，不监视剪贴板。
- 缺资料明确标注，不猜编码或拆分；学习信息对应实际显示汉字，转换字形标注来源。
- 原字/简体/繁体三档，默认原字；一对多列候选，不猜语境，不改已上屏内容，不做地区词汇替换。
- 竖排九候选、15pt。候选字体可选霞鹜文楷（默认）或楷体，未安装时回退微软雅黑 UI；编码与序号用 Cascadia Mono（回退 Consolas），窗口文字用微软雅黑 UI。配色主题可选琥珀（默认）、墨、竹、夜与自定义；自定义只取背景、文字、高亮、强调四基色，其余按比例混色推导，保存与载入均校验无蓝（蓝分量不高于红、绿）且文字对比度不低于 4.5:1。为保证换电脑可用，霞鹜文楷（虎码融合字根版）、Cascadia Mono 与 TumanPUA 随包：取自官方渠道，按 `resources/fonts.lock.json` 锁定大小与 SHA256，由安装包全机安装（已有同名文件不覆盖，卸载不删除）；不走安装包时 `install-fonts` 为当前用户安装（无需管理员，先全部校验再复制，不覆盖内容不同的同名文件，已登记的路径不重复登记），候选窗按字体名取用，DLL 仍不读盘；楷体与微软雅黑 UI 为微软系统字体，不随包分发。原生 UI，配色字节序和字根覆盖实测。所有界面（候选窗、查字/设置窗）不得出现任何蓝色，含系统强调色与选中高亮（用户自己开启的高对比度除外）。
- 设置仅四码自动上屏、输出字形、常用字过滤、学习提示、候选字体与配色主题（含自定义四基色），从查字窗进入；保存成功即热重载到后台，新会话立即使用，组合中的会话在本次组合结束后换上，无需重启后台。
- 不做 librime、Lua、OpenCC 运行库、数据库、英文补全、计算器、日期、Emoji、网址启动或通用 YAML 配置兼容。

## 架构与接口
每登录会话一个后台，固定引擎线程，查字/设置另有固定 UI 线程；宿主内只有 TSF DLL，经认证 IPC 连接，候选窗由 DLL 在宿主 TSF 线程内绘制。后台主动/随登录启动，输入回调不拉起程序。严重故障取消组合、放行原键，由用户重启；不再要求双后台自动监督。

| 模块 | 职责 | 项目内直接依赖 |
|---|---|---|
| contracts | 按键、候选、学习信息、会话、协议 | 无 |
| engine | 纯 Rust 状态机、索引、字形转换 | contracts |
| ipc | 编解码、认证、截止时间、取消 | contracts |
| tsf | TIP DLL、组合、上屏、宿主内候选窗 | contracts、ipc |
| ui | 查字/设置原生窗口与操作事件 | contracts |
| app | 数据加载、配置、调度、生命周期、组装 | contracts、engine、ipc、ui |

tsf 随真实 `ITfEditSession` / `ITfCompositionSink` 编辑组件加入，COM 绑定使用锁定 `windows` / `windows-core`，不手写系统 vtable；这些平台依赖只允许在 tsf，不能进入 contracts/engine。ui 随独立查字工具加入。核心不做文件/进程/窗口操作；UI 不直接调用 engine；contracts/engine 禁止 unsafe。

tsf 同时产出 cdylib（TIP DLL）和 rlib（测试）。TIP 只含类工厂、`ITfTextInputProcessorEx`、`ITfKeyEventSink`、`ITfThreadMgrEventSink`、编辑组件和候选窗；注册类别含 `GUID_TFCAT_TIP_KEYBOARD`、`GUID_TFCAT_TIPCAP_IMMERSIVESUPPORT`、`GUID_TFCAT_TIPCAP_SYSTRAYSUPPORT`；`DllCanUnloadNow` 恒为 `S_FALSE`。延迟只记固定区间计数，不记输入内容。

查字/设置窗采用 Win32 标准 EDIT/BUTTON/LISTBOX/STATIC 控件和系统可访问性基础，不启用系统控件主题（其悬停、焦点、勾选为蓝色），由父窗口与子类化按钮按主题自绘：查字为字列表加详情卡，设置为开关与分段单选卡片；窗口只处理 contracts 进程内请求/回复，应用层固定工作线程独占词表和设置租约。请求/回复队列各容量一、一次仅一个在途动作；内核事件与 Windows 消息共同唤醒 UI，不定时轮询、不跨线程传递窗口句柄。关闭先断开通道，再实际 join；不把超时当作线程已退出。查字/设置窗在后台进程的固定 UI 线程：首次唤起才建窗口，关闭只隐藏（连同设置窗与草稿），后台停止时唤起邮箱断开、窗口销毁，UI 与工作线程退出并实际 join 后才释放受管目录租约。工作线程与引擎线程共用只读词表，工作线程独占受管目录租约与设置事务。管理端以 `Show`/`Shown` 唤起（与 `Stop` 同样核对调用进程映像），唤起前 `AllowSetForegroundWindow` 放行前台切换；后台未运行时唤起进程自身成为后台并立即显示。保存成功后，工作线程把设置放进只留最新一份的交接槽并以内核事件唤醒引擎线程；引擎线程每轮先取交接槽再处理请求，新会话随 `Open` 使用新设置，已打开的会话在无组合的下一次请求时换上（组合中更换会改掉宿主已显示的候选与编号）。查字结果不受输入设置影响，字形字体与配色跟随设置。

查字与设置各自保留状态提示，设置保存不重写查字资料或破坏选区；重复唤起设置不丢草稿。异步回复只能恢复本前台窗口丢失的控件焦点，不抢其他应用或用户已切换的焦点；输入框的 IME 组合、展开的字形下拉框优先处理确认/取消。内部消息错配视为故障退出，不继续消费不确定回复。

移除 Rime 方案和 X11 键码，使用逻辑按键、输入模式、输出字形和结构化学习信息；协议升版并拒绝旧版本。焦点、光标、选字和快照绑定会话/版本；上屏由 TSF 完成，查询不产生提交。

协议 v5 删除 v4 的宿主通知、`TakeSelection` 和焦点光标矩形，直接拒绝 v4。按键/选字绑定焦点代次，焦点请求只报告取得/失去（`focused` 布尔值），光标与候选位置留在宿主进程。后台进程内候选窗失去光标与点击回送依据，随 A 批删除；进程内候选预览工具与 ui 候选窗已在 B2 随宿主内候选窗落地删除。应用调度为认证后的连接分配不复用宿主编号，正文不得自报宿主；请求序号、会话编号和焦点代次在各宿主内单调，同时在线最多 16 宿主、合计 64 会话。焦点切换取消旧的未上屏组合，旧宿主迟到的失焦不能清空新宿主状态。协议 v6 在 `InputState` 增加 `ascii_punctuation`，使 TSF 能按上次状态精确判定未组合时的标点。协议 v7 在 `Options` 增加配色主题、自定义四基色与候选字体，随 `InputState` 交给宿主内候选窗，DLL 不读盘；并加入管理消息 `Show`/`Shown`。协议 v8 删除 `InputState.notice`，候选窗不再显示提示行；直接拒绝 v2–v7。旧 `settings.json` 缺少新字段即被拒绝（开发期不兼容），须删除后重新保存。

跨进程传输：每登录会话固定一个所有权管道和 16 个预建请求管道，均保持首实例约束；一个完成线程只唤醒固定反应器，不执行引擎。后台随机代次和宿主编号由 Hello/Welcome 握手发放。

管道安全描述符为 `D:P(A;;<客户端权限>;;;<登录 SID>)(A;;<客户端权限>;;;AC)S:(ML;;NW;;;LW)`。客户端权限只含读写，不含创建实例；AC（ALL APPLICATION PACKAGES）满足沙箱双重访问检查，低完整性标签允许 AppContainer 写入，Untrusted 级沙箱仍被拒绝；不授予 Everyone 或 LPAC（ALL RESTRICTED APPLICATION PACKAGES）。“沙箱令牌含登录 SID”是前提，须由 AppContainer 子进程正反例实测。实测表明只派生 AppContainer SID 时 `CreateProcessW` 返回 `ERROR_FILE_NOT_FOUND`，必须先注册配置；因此 AC 子进程测试创建并删除临时配置（当前用户注册表与 Packages 目录），默认忽略，经用户授权后显式运行，不计入常规 passed。低完整性与 Untrusted 子进程只降低当前令牌完整性，纳入常规测试。

认证两侧都不读取对方令牌。后台只凭 DACL、拒绝远程客户端和 `GetNamedPipeClientSessionId` 同会话接纳宿主，不打开宿主进程；宿主断开由已连接管道的常驻读失败发现。宿主核对管道所有者 SID 等于自身用户 SID、服务端会话等于自身会话，并以 `PROCESS_QUERY_LIMITED_INFORMATION` 打开服务端进程核对映像路径；为此后台启动时只向自身进程 DACL 追加 `(A;;0x1000;;;AC)`。停止命令仍打开调用进程，要求其映像等于后台管理程序。不会按输入启动程序。

宿主即一个 TIP 线程实例，在第一个需要引擎的按键编辑会话内才连接，计入同一截止时间，激活阶段不连接。后台始终保留至少一个空闲监听槽：最后一个空槽被占用或会话数达到上限时，回收最久未用、非当前焦点、无组合且无未读字节的宿主；待重建的槽位视为空槽，被回收连接以 `DisconnectNamedPipe` 立即断开。宿主发送前以非阻塞 `PeekNamedPipe` 发现已断开时，在同一截止时间内重连一次；重连后宿主编号、序号和会话全部重建，须先 Open/Focus 再发按键。请求已写出而回复读取失败视为结果不确定，不重放。回收判定与宿主写入之间存在不可消除的窄竞态，此时按结果不确定处理（取消组合、放行原键）。停止确认写完即结束服务，不再挂读取，避免对端先关闭导致已确认的停止丢失。

每个请求管道一个在途操作。握手有界，正常请求首段后组帧/调度/回复共享绝对期限；完成事件和到期共用一次内核等待，不等待宿主进程句柄，因此不受 64 个等待对象上限约束。设置启动时读入，查字窗保存后经交接槽热重载，输入期间不读盘。

改变引擎状态的请求只在取得编辑锁后、于 `DoEditSession` 内发出；拿不到锁时后台状态未变，放行原键。按键路径在 `OnKeyDown` 内请求 `TF_ES_SYNC`，同一会话发送按键、写组合、取光标矩形并更新候选窗，共用 50ms 截止；同步调用返回后撤销该会话。候选点击由窗口过程投递私有消息后请求 `TF_ES_ASYNCDONTCARE`，同一时刻最多一个待执行点击会话；会话开始时核对焦点代次、本地展示编号和组合文本未变，再发 `Select`，50ms 预算从会话开始计算。结果只在会话内取得并写入，不存在迟到提交。`OnTestKeyDown` 不发输入请求，只按上次状态本地判定；判定吃掉的键必须是引擎在该状态下必处理的子集，由测试穷举核对。真实宿主实测（Notepad++）表明预判吃下、处理时放行的原键不会交还应用，因此预判前必须确认后台可用：已有连接以非阻塞检查复用，否则在 50ms 期限内只做连接握手，连不上即不吃键。宿主终止组合时只做标记，下一按键会话先发 `Clear`。判定规则为 contracts 的 `InputState::consumes`，引擎测试在全部可达状态下核对其与 `handled` 完全一致；`OnKeyDown` 同样先按此判定，不被吃的键不发 IPC。

文档焦点变化（`ITfThreadMgrEventSink::OnSetFocus` 或按键上下文更换）不发 IPC：旧编辑器失效并取消自有组合（同步锁被拒时排队一次只删一致自有组合的异步取消），下一按键会话先发 `Focus`。后台以 `NotFocused`/`StaleFocus` 拒绝按键（另一宿主已取得焦点）时，被拒的键未被处理，同一截止时间内重新报告焦点后补发一次，不算重放；再次被拒即作废连接、放行原键。

按键映射：Alt/AltGr 组合一律放行；Ctrl 只认 `Ctrl+.`（中英标点）与组合中的 `Ctrl+L`（学习信息），其余 Ctrl 快捷键放行；单击 Shift（期间无其他键、无 Ctrl/Alt）切换中英；上/左为前一候选、下/右为后一候选；字符按当前布局以 `ToUnicodeEx` 不改变键盘状态取得，死键与多字符放行。TSF 只把按键交给键盘开闭状态（`GUID_COMPARTMENT_KEYBOARD_OPENCLOSE`）为“开”的 TIP，新线程管理器初值为空即关闭；TIP 激活时打开它，并在激活期间监听，被宿主或开关热键关闭即重新打开，中英文只由本输入法自己的状态切换，停用后不再干预。

编辑组件只替换自有组合或空插入点，先核对原组合文本与光标；只读上下文、用户非空选区拒绝写入，且在调用后台前判定，后台状态因此不变。外部改写或光标移出旧组合时只结束旧组合、不改正文，后台先 `Clear` 后按当前插入点处理本键。后台结果只在本会话内取得，不存在旧快照写入。已确认的提交单独报告，后续清理失败也不得重放或删除已提交前缀。

候选窗按微软 IME 要求在宿主进程内创建：TSF 线程惰性创建、停用时销毁，以 `ITfContextView::GetWnd`（失败时用 `GetFocus`）作 owner，与宿主处于同一 z-order 层级；窗口类用 DLL 模块句柄注册。不用标准按钮，改为自绘与命中测试，避免同线程控件取得焦点、激活弹窗并终止组合。显示、隐藏和移动时发 `EVENT_OBJECT_IME_SHOW/HIDE/CHANGE`；UIA 遵循 IME 约定：AutomationId 为 `IME_Candidate_Window`，显隐发 MenuOpened/MenuClosed，选中项发选中事件，Name 为候选字。不声明 DPI 感知，跟随宿主进程并使用同一上下文的 `GetTextExt` 坐标。候选数据取自按键回复的 `InputState`，不另走 IPC；更新时递增本地展示编号并取消旧鼠标捕获。

候选窗实现细节（B2）：组合矩形在按键/点击会话写入后以同一 cookie 的 `GetTextExt` 取得，宿主无布局时退回本线程 `GetGUIThreadInfo` 光标，仍无位置则不显示；有候选且处于组合时显示，否则隐藏（空码时编码只留在组合下划线里）。窗口过程只按句柄在本线程登记表中以弱引用找回候选窗，不在窗口数据里存业务指针。按下与抬起落在同一行才投递私有点击消息（展示编号 + 页内序号）；同一展示最多受理一个待执行点击，展示更新或会话结束即解除。点击会话核对组合文本未被改写（不要求光标在末端），不结束旧组合、不请求清空；宿主已终止组合时拒绝并把清空留给下一按键。UIA 根元素与候选项以 COM 线程模型声明，候选项运行时编号含展示编号，展示更新后旧元素报告不可用；HelpText 为编码提示；UIA 的选择操作被拒绝，选字只经编辑会话。只有 UIA 客户端监听时才构造元素发事件。产品要求界面不得出现任何蓝色：候选窗取选项中的主题配色，不用系统强调色或选中色，仅在用户开启高对比度时改用其系统颜色。外观（10-23 重设计）：高亮行为圆角底色加左侧指示条，注释列对齐，页脚（仅可翻页或拼音反查时出现）以分隔线隔开；纯 GDI，内存位图双缓冲、库存 DC 画刷改色，字体按 DPI 与候选字体缓存并核对实际字体名回退；Win11 由 DWM 画圆角与主题色边框，Win10 退回直角自绘外框。宿主终止组合时立即收起候选窗；外观数据不经 DLL 读盘。

会话交换结论分三种：未发出或后台明确未处理（旧快照、焦点被夺）为“跳过”，不写入、不作废；结果不确定为“丢失”，同一会话撤回仍一致的自有组合并放行原键；其余为“写入”。写入阶段失败同样在会话内撤回自有组合，下次按键先 `Clear`。停用时显式断开管道，不依赖其余引用何时释放。

队列、查询和结果页有界；TSF 单次主动等待总预算 50ms，连接/编码/接收共享绝对截止时间。故障不重放、不交付迟到提交；不持锁阻塞、不逐键建线程或记录输入。

DLL 传输的首版安全策略采用显式进程期驻留：默认 `Runtime::new` 仍拒绝 DLL，专用入口 `new_process_resident` 在激活阶段用系统 PIN 固定完成回调所在模块，不支持热卸载。停止先取消/释放管道和取消令牌，再以绝对期限调用 `shutdown` 关闭准入并等待资源所有权排空；超时保留关闭状态和仍存活的资源，可再次等待。排空不等于完成线程已返回，回调尾部仍由模块 PIN 保护；不得在 DllMain 或输入回调创建/排空运行时。未来 TSF 必须按此驻留策略报告不可热卸载；安装/升级不得将关闭成功当作 DLL 已从宿主卸载。每个宿主进程一个进程期驻留 `Runtime`，由首次激活创建，供各 TIP 线程的连接共用；它是传输基础设施而非业务状态，各线程的连接与会话状态仍归各自 TIP 实例。

## 数据与配置
- Rust 工具只转换锁定单字表、常用字集、拼音单字/读音、拆分、简繁映射和指定外观数据。复用数据不是兼容运行时。
- 校验来源、大小/hash、路径/格式；原件只读，生成版本化 JSON 数据包及来源清单；失败不覆盖旧文件。
- 启动校验并构建排序索引，二分查询；输入时不读文件或扫描整表。不引入数据库、自定义二进制格式。
- 保留多编码/多音字/多拆分码，完整码与实际码交叉检查，不仅凭长度判断全码。
- 独立 APPDATA，复用目录占用、链接拒绝、配置事务替换；不导入个人 Rime 数据。安装版后台与查字窗使用程序目录的 `tiger-v1.json` 与 `%APPDATA%TigerType`（不存在则新建，已有目录须带所有权标记）；开发期 `serve <包> <目录>` 仍可指定独立目录。
- 安装包由 Inno Setup 6.7 编译（用户批准的唯一非 Rust 工具；`.iss` 只含声明与安装前停后台、改名占用文件的少量 Pascal），Rust 打包驱动 `--example package` 先构建 release、校验字体与语言文件、由锁定资源重新生成数据包并核对脚本与字体清单一致。两种 MSVC 目标静态链接 CRT。安装需管理员，固定装到 Program Files（不提供改目录）；先放程序再分别以 64/32 位注册 DLL；字体全机安装；HKLM Run 登记 `serve` 使各用户登录时以普通权限启动自己的后台，安装结束以原用户身份启动一次；开始菜单只有“查字与设置”；不添加或切换键盘。`tigertype.exe` 为 GUI 子系统，从终端运行时借用父控制台，无控制台时 `serve`/`lookup-window` 失败弹错误框。升级先以原用户身份 `stop`，再把仍在使用的旧程序与 DLL 改名并登记重启后删除；卸载先请求停止后台、注销 DLL、删除程序与自启项，占用文件重启后删除，保留用户数据。
- TIP DLL 与后台程序须位于 Program Files，或位于已对 ALL APPLICATION PACKAGES 授予读取/执行的独立目录，否则 AppContainer 宿主无法加载；DLL 不读取数据文件。
- 注册入口为 DLL 导出的 `DllRegisterServer`/`DllUnregisterServer`（regsvr32，须管理员）：COM 类写入 HKLM\SOFTWARE\Classes（`InprocServer32`、`ThreadingModel=Apartment`），以 `ITfInputProcessorProfileMgr` 登记简体中文（0x0804）语言配置（默认启用、暂无图标），以 `ITfCategoryMgr` 登记键盘 TIP、沉浸式与托盘三类别；注册前要求 DLL 为绝对路径且同目录有后台程序，任一步失败回滚；注销尽力移除全部内容，重复注销时系统对未登记项的报错照实返回。x64/x86 DLL 放同一目录（x86 改名）共用一个后台，分别由 System32 与 SysWOW64 的 regsvr32 注册；32 位 COM 类经 WOW64 写入 32 位视图。注册测试只核对注册内容，并在临时私有配置单元（`RegLoadAppKeyW`）中验证读写，不写系统或用户注册表。

```powershell
cargo run --locked --offline -p tigertype-app --example check
```

## 迁移与验收
1. 更新四份主文档，按用户明确授权删除旧路线源码、测试、文档和归档；不清理锁定资源或测试报告，不整仓重置。
2. 数据/纯 Rust 核心、协议及调用方/测试同步迁移，架构门禁同批生效；无宽泛豁免。
3. 独立查字/设置先验证数据与字形，再接候选窗和单后台，不提前注册。
4. 先完成 IPC DLL 回调驻留/关闭，再接 TSF/混合位数/多宿主；不得直接移除 EXE 限制。按三批推进：A 传输与认证（安全描述符、双侧认证、删除通知通道与后台候选窗、懒连接与槽位回收、协议 v5）；B 最小 TIP 与宿主内候选窗，分两步：B1 类工厂、按键/焦点 sink、按键映射与本地判定、统一按键编辑会话（协议 v6）；B2 宿主内候选窗、UIA/WinEvent、点击异步会话，删除候选预览与 ui 候选窗；C 先实现注册/注销入口，再经授权在暂存目录注册后做真实宿主验收，验收后注销。
5. 安装包已实现；各电脑上的安装由用户执行，与旧输入法并存，卸载保留数据并长期验收。

验收覆盖：简/全码、稳定顺序、两种四码模式、空码/翻页/退格/清屏、非 BMP；多音字、ü/v、多编码、缺资料、简繁一对多与去重、实际字形与码对应；查询不改变会话；超时/卡死/断连/迟到/旧快照不重复上屏；坏包/配置失败/路径攻击保留旧数据；故意架构违规失败。

传输与宿主接入另覆盖：AppContainer 和低完整性子进程可连接、Untrusted 级被拒，沙箱与普通客户端都不能抢建实例；其他用户抢注管道名被宿主拒绝；第 17 个宿主触发回收，被回收宿主不丢键、不重放；编辑锁被拒时放行原键，过期点击不上屏。

UI 验收覆盖配色、字体、布局、DPI、边缘定位、无障碍及常用应用/x86/管理员/UWP 宿主（开始菜单搜索、设置搜索框）；候选窗 UIA 约定和 IME WinEvent 用读屏器实测。性能目标：预热 P95≤10ms、P99≤25ms、主动等待≤50ms；统计后台+宿主增量，两小时压力和八小时使用。微基准、历史数据、测试数量不替代验收。

旧故障因组件退役退出当前范围，不宣称修复。
