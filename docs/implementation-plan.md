## 产品范围
- 产品名统一为 TigerType，crate 使用 `tigertype-*`、程序为 `tigertype.exe`，工作区目录为 `TigerType`，正式数据目录为 `%APPDATA%\TigerType`。窗口、IPC 管道/帧标识及目录所有权标记同步使用新名称；开发期不兼容旧名称的程序或受管目录，不迁移或改写已有数据。
- Windows 10/11 x64、x86 宿主，含管理员和 UWP/AppContainer（沉浸式）宿主；Rust 专用单字/词引擎，不兼容 Rime。LPAC 宿主、UILess 模式和触摸键盘避让暂不支持；连不上后台时放行原键。
- 单字码表与 tigress_ci 词码按权重降序、原始行序稳定排序；不造词、不调频。
- 默认四码待选、下一码顶屏；可开启四码唯一自动上屏，唯一性在过滤/转换/去重后判定。
- 空格选字、数字选重、分号次选、引号三选、翻页、退格、清屏、中英文切换；空码不误上屏；满四码空码时下一码顶上清屏（同小狼毫 `auto_clear: max_length`），无对应候选的选重、越界翻页等静默忽略，不弹文字提示（主流输入法均不弹）。
- 普通输入默认常用字集，可切全字集；查字始终全字集。普通输入默认隐藏学习信息，可临时显示。
- 反引号单字拼音反查：无调全拼、ü/v、多音字、可选字上屏；无双拼、整句、模糊纠错。
- 独立查字窗输入拼音/虎码/粘贴汉字或词，显示可用编码、完整编码、读音、拆分；词查询保留词码，复制由用户点击，不监视剪贴板。
- 缺资料明确标注，不猜编码或拆分；学习信息对应实际显示汉字，转换字形标注来源。
- 原字/简体/繁体三档，默认原字；一对多列候选，不猜语境，不改已上屏内容，不做地区词汇替换。
- 竖排候选、15pt，每页 3–9 个（默认 5），候选多于一页时才在页脚显示翻页指示，拼音反查时页脚另有“拼音”标签。候选字体可选霞鹜文楷（默认）或楷体，未安装时回退微软雅黑 UI；编码与序号用 Cascadia Mono（回退 Consolas），窗口文字用微软雅黑 UI。配色主题可选琥珀（默认）、墨、竹、玫红与自定义；自定义四基色在设置页点色块从无蓝色板选取或直接输入色值，即时校验并热加载。玫红取自小狼毫配色 MacRoseo（白底黑字，高亮候选无底色、只把字染成玫红，原色 #FA114F 等比压暗为 #E8114E 以达 4.5:1）；保存与载入均校验无蓝且文字对比度不低于 4.5:1。为保证换电脑可用，霞鹜文楷（虎码融合字根版）、Cascadia Mono 与 TumanPUA 随包：取自官方渠道，按 `resources/fonts.lock.json` 锁定大小与 SHA256，由安装包全机安装。原生 UI，所有界面不得出现任何蓝色（高对比度除外）。
- 设置窗分“输入、外观、快捷键、高级”四区（左侧导航，内容超出窗口时纵向滚动），修改即时保存并热加载，不设保存/取消按钮；保存在途时的新改动不排队，回复后按最新草稿与已确认设置比较再存一次，保存失败时控件撤回已确认设置并说明原因。输入区：单字/词输入模式（默认单字）、仅常用字、四码唯一自动上屏、输出字形；外观区：按草稿现画的候选窗预览、候选字体、每页候选数、显示拆分与编码（开启后候选注释为小狼毫虎码方案同款〔拆分 · 编码〕，缺拆分时只列编码；默认关闭）、配色主题卡片与自定义四色（色块点开 8×4 无蓝色板或输入 `#RRGGBB`，提示最低对比度或不可用原因）；快捷键区只读列出现有快捷键（数字键范围随每页候选数）；高级区用系统默认编辑器打开受管 `config/settings.toml`，手工修改后点“重新载入”生效（格式错误时保留当前设置并指出行号），另有版本信息。`settings.toml` 按带中文注释的固定模板写出（`[input]`、`[candidate]`、`[theme]`、`[theme.custom]` 四节，颜色写作 `"#RRGGBB"`），读回时缺键、多键、类型或范围不符都拒绝；首次运行写出默认文件；界面保存按模板重写，用户自加的注释不保留；文件被外部修改后界面保存被拒，须先重新载入。旧 `settings.json` 不再读取（开发期不兼容）。当前程序任务栏输入法图标右键菜单前三项写当前状态（中文/英文、半角/全角、中文标点/英文标点），点击即翻转，其下为查字、设置；全角与标点开关仍为会话状态。保存成功即热重载到后台，新会话与无组合的会话立即使用；组合中的会话在本次组合结束时换上，无需重启后台。
- 不做 librime、Lua、OpenCC 运行库、数据库、英文补全、计算器、日期、Emoji、网址启动或通用 YAML 配置兼容。

## 架构与接口
每登录会话一个后台，固定引擎线程，查字/设置另有固定 UI 线程；宿主内只有 TSF DLL，经认证 IPC 连接，候选窗由 DLL 在宿主 TSF 线程内绘制。后台主动/随登录启动，输入回调不拉起程序。严重故障取消组合、放行原键，由用户重启；不再要求双后台自动监督。

| 模块 | 职责 | 项目内直接依赖 |
|---|---|---|
| contracts | 按键、候选、学习信息、会话、协议 | 无 |
| engine | 纯 Rust 状态机、索引、字形转换 | contracts |
| ipc | 编解码、认证、截止时间、取消 | contracts |
| tsf | TIP DLL、组合、上屏、宿主内候选窗 | contracts、ipc |
| ui | 查字/设置原生窗口与操作事件 | contracts |
| app | 数据加载、配置、调度、生命周期、组装 | contracts、engine、ipc、ui |

tsf 随真实 `ITfEditSession` / `ITfCompositionSink` 编辑组件加入，COM 绑定使用锁定 `windows` / `windows-core`，不手写系统 vtable；这些平台依赖只允许在 tsf，不能进入 contracts/engine。ui 随独立查字工具加入。核心不做文件/进程/窗口操作；UI 不直接调用 engine；contracts/engine 禁止 unsafe。

tsf 同时产出 cdylib（TIP DLL）和 rlib（测试）。TIP 只含类工厂、`ITfTextInputProcessorEx`、`ITfKeyEventSink`、`ITfThreadMgrEventSink`、编辑组件、候选窗和任务栏输入法图标；图标是 `GUID_LBI_INPUTMODE` 语言栏按钮，激活时登记、停用时注销，图标每次现画（像微软拼音、小狼毫那样只画“中”或“英”一个字、底全透明，字色随任务栏深浅：激活时读一次系统“Windows 模式”，深色白字、浅色近黑字；按回复中的英文模式切换并通知系统重取图标与提示，不读盘；品牌印章另由输入法配置图标与通知区图标显示），按钮只声明普通按钮样式，系统右键只调用 `OnClick(右键)`、不调用 `InitMenu`，因此点击都在 `OnClick` 内处理：左键切换中英——不在按键事件内拿不到同步编辑会话，有自有组合时复用点击选字的异步编辑会话交换 `ToggleAscii`（后台把编码原样上屏），无组合时不碰文档直接交换并先让后台丢弃宿主已终止的残留组合；右键菜单由 TIP 以本线程临时隐藏窗口为所有者 `TrackPopupMenuEx` 自绘弹出（无蓝色，项保留文字供读屏器），弹出前在单次回调预算内确认后台可连接并取上次回复的中英、标点与全角状态，状态项写当前状态（分隔线为自绘分隔项，方向键跳过），选“查字/设置”经本宿主已有连接请后台唤起窗口，选中英项同左键，选全角或标点项则不碰文档直接交换 `ToggleFullShape`/`TogglePunctuation`；注册类别含 `GUID_TFCAT_TIP_KEYBOARD`、`GUID_TFCAT_TIPCAP_IMMERSIVESUPPORT`、`GUID_TFCAT_TIPCAP_SYSTRAYSUPPORT`；`DllCanUnloadNow` 恒为 `S_FALSE`。延迟只记固定区间计数，不记输入内容。

查字/设置窗采用 Win32 标准 EDIT/BUTTON/LISTBOX/STATIC 控件和系统可访问性基础，不启用系统控件主题（其悬停、焦点、勾选为蓝色），由父窗口与子类化按钮按主题自绘：查字窗默认 520×400，为查询框（回车查询）、横排字块（单行多列自绘列表）与详情卡（田字格字形、编码键帽、读音、拆分字块、复制当前字）；设置窗固定 720×520，左侧导航按单选组切换分区，各区为开关行、分段单选与卡片，只布局并显示当前分区的控件，滚动位置以整数存于窗口数据；色板为自绘弹出菜单（经同一模态等待）；图标字体用 Segoe Fluent Icons（回退 MDL2 Assets）；窗口只处理 contracts 进程内请求/回复，应用层固定工作线程独占词表和设置租约。请求/回复队列各容量一、一次仅一个在途动作；内核事件与 Windows 消息共同唤醒 UI，不定时轮询、不跨线程传递窗口句柄。关闭先断开通道，再实际 join；不把超时当作线程已退出。菜单（托盘右键、窗口系统菜单）与移动/缩放是系统模态循环，期间事件循环不运行：进入时由系统线程池代等唤起邮箱事件，有信号（唤起或后台停止）即投递消息让 UI 线程收起菜单、取消移动/缩放并重新置事件，退出模态时阻塞注销等待，停止因此不必等用户操作。查字/设置窗在后台进程的固定 UI 线程：该线程启动即挂通知区图标（前台程序正用本输入法、任务栏已显示输入法图标时隐藏：持有输入焦点的宿主线程以 `Indicator(取得|失去)`/`Noted` 报告，后到的取得覆盖先前持有者、失去只清除自己、断开等同失去，持有者不被槽位回收，有无持有者经只留最新值的交接槽交给 UI 线程；打开溢出区等操作把前台交给任务栏面板时任务栏仍显示先前程序的输入法图标，UI 线程以进程外前台切换 WinEvent 判断，前台是任务栏面板时维持隐藏，换到其他窗口再定；隐藏的顶层窗口接收图标回调与 TaskbarCreated 广播，资源管理器未就绪或重启后重新挂上；版本 4 回调，单击/Enter 打开设置页，右键或菜单键弹出自绘菜单，配色按主题、无系统蓝色高亮，菜单项保留文字供读屏器；图标为虎码印章（琥珀圆角方块、米白霞鹜文楷“虎”字，大尺寸带两侧虎纹，GDI 四倍超采样现画），与输入法配置图标、查字/设置窗图标一致；右键菜单为查字、设置（带图标），后台退出时删除），查字/设置窗首次唤起才建，关闭只隐藏（连同设置窗，未填完的色值丢弃），后台停止时唤起邮箱断开、窗口销毁，UI 与工作线程退出并实际 join 后才释放受管目录租约。工作线程与引擎线程共用只读词表，工作线程独占受管目录租约与设置事务。唤起消息 `Show(查字|设置)`/`Shown` 只投递信号、不改数据，已握手的宿主（图标菜单）与管理端都可发送，不核对映像；宿主上的唤起不占会话，成功后连接照常用于输入。唤起方先 `AllowSetForegroundWindow` 放行前台切换；设置页可在查字窗隐藏时单独显示，并有自己的任务栏按钮。管理端唤起时后台未运行，则唤起进程自身成为后台并立即显示查字窗。保存成功后，工作线程把设置放进只留最新一份的交接槽并以内核事件唤醒引擎线程；引擎线程每轮先取交接槽再处理请求，新会话随 `Open` 使用新设置；已打开的会话在下一次请求时交给引擎，无组合即换上，组合中由引擎暂存、在本次组合结束时换上（含顶屏与退格删空，已显示的候选与编号不重算）。查字结果不受输入设置影响，字形字体与配色跟随设置。

查字与设置各自保留状态提示，设置保存不重写查字资料或破坏选区；设置窗控件即草稿，重复唤起保留当前分区，隐藏后重开恢复为已确认设置。异步回复只能恢复本前台窗口丢失的控件焦点，不抢其他应用或用户已切换的焦点；输入框的 IME 组合、展开的字形下拉框优先处理确认/取消。内部消息错配视为故障退出，不继续消费不确定回复。

移除 Rime 方案和 X11 键码，使用逻辑按键、输入模式、输出字形和结构化学习信息；协议升版并拒绝旧版本。焦点、光标、选字和快照绑定会话/版本；上屏由 TSF 完成，查询不产生提交。

协议 v5 删除 v4 的宿主通知、`TakeSelection` 和焦点光标矩形，直接拒绝 v4。按键/选字绑定焦点代次，焦点请求只报告取得/失去（`focused` 布尔值），光标与候选位置留在宿主进程。后台进程内候选窗失去光标与点击回送依据，随 A 批删除；进程内候选预览工具与 ui 候选窗已在 B2 随宿主内候选窗落地删除。应用调度为认证后的连接分配不复用宿主编号，正文不得自报宿主；请求序号、会话编号和焦点代次在各宿主内单调，同时在线最多 16 宿主、合计 64 会话。焦点切换取消旧的未上屏组合，旧宿主迟到的失焦不能清空新宿主状态。协议 v6 在 `InputState` 增加 `ascii_punctuation`，使 TSF 能按上次状态精确判定未组合时的标点。协议 v7 在 `Options` 增加配色主题、自定义四基色与候选字体，随 `InputState` 交给宿主内候选窗，DLL 不读盘；并加入管理消息 `Show`/`Shown`。协议 v8 删除 `InputState.notice`，候选窗不再显示提示行。协议 v9 让 `Show` 携带目标窗口（查字/设置），并允许已握手的宿主发送。协议 v10 加入 `Indicator(bool)`/`Noted`：宿主线程取得/失去输入焦点（`ITfThreadFocusSink`，及在持有焦点的线程中激活）时报告，新连接补报仍持有的焦点；协议 v11 在配色主题中加入玫红，`Palette` 增加高亮候选字色 `chosen`；加入 `Key::ToggleFullShape` 与 `InputState.full_shape`；直接拒绝 v2–v10。协议 v13 在 `Options` 增加每页候选数 `page_size`（3–9），候选页大小随设置变化，IPC 选字索引上限为最多候选数 9，引擎按本页实际大小判越界；直接拒绝 v2–v12。

跨进程传输：每登录会话固定一个所有权管道和 16 个预建请求管道，均保持首实例约束；一个完成线程只唤醒固定反应器，不执行引擎。后台随机代次和宿主编号由 Hello/Welcome 握手发放。

管道安全描述符为 `D:P(A;;<客户端权限>;;;<登录 SID>)(A;;<客户端权限>;;;AC)S:(ML;;NW;;;LW)`。客户端权限只含读写，不含创建实例；AC（ALL APPLICATION PACKAGES）满足沙箱双重访问检查，低完整性标签允许 AppContainer 写入，Untrusted 级沙箱仍被拒绝；不授予 Everyone 或 LPAC（ALL RESTRICTED APPLICATION PACKAGES）。“沙箱令牌含登录 SID”是前提，须由 AppContainer 子进程正反例实测。实测表明只派生 AppContainer SID 时 `CreateProcessW` 返回 `ERROR_FILE_NOT_FOUND`，必须先注册配置；因此 AC 子进程测试创建并删除临时配置（当前用户注册表与 Packages 目录），默认忽略，经用户授权后显式运行，不计入常规 passed。低完整性与 Untrusted 子进程只降低当前令牌完整性，纳入常规测试。

认证两侧都不读取对方令牌。后台只凭 DACL、拒绝远程客户端和 `GetNamedPipeClientSessionId` 同会话接纳宿主，不打开宿主进程；宿主断开由已连接管道的常驻读失败发现。宿主核对管道所有者 SID 等于自身用户 SID、服务端会话等于自身会话，并以 `PROCESS_QUERY_LIMITED_INFORMATION` 打开服务端进程核对映像路径；为此后台启动时只向自身进程 DACL 追加 `(A;;0x1000;;;AC)`。停止命令仍打开调用进程，要求其映像等于后台管理程序；唤起窗口不改数据，不做此核对。不会按输入启动程序。

宿主即一个 TIP 线程实例，在第一个需要引擎的按键编辑会话内才连接，计入同一截止时间，激活阶段不连接。后台始终保留至少一个空闲监听槽：最后一个空槽被占用或会话数达到上限时，回收最久未用、非当前焦点、无组合且无未读字节的宿主；待重建的槽位视为空槽，被回收连接以 `DisconnectNamedPipe` 立即断开。宿主发送前以非阻塞 `PeekNamedPipe` 发现已断开时，在同一截止时间内重连一次；重连后宿主编号、序号和会话全部重建，须先 Open/Focus 再发按键。请求已写出而回复读取失败视为结果不确定，不重放。回收判定与宿主写入之间存在不可消除的窄竞态，此时按结果不确定处理（取消组合、放行原键）。停止确认写完即结束服务，不再挂读取，避免对端先关闭导致已确认的停止丢失。

每个请求管道一个在途操作。握手有界，正常请求首段后组帧/调度/回复共享绝对期限；完成事件和到期共用一次内核等待，不等待宿主进程句柄，因此不受 64 个等待对象上限约束。设置启动时读入，查字窗保存后经交接槽热重载，输入期间不读盘。

改变引擎状态的请求只在取得编辑锁后、于 `DoEditSession` 内发出；拿不到锁时后台状态未变，放行原键。按键路径在 `OnKeyDown` 内请求 `TF_ES_SYNC`，同一会话发送按键、写组合、取光标矩形并更新候选窗，共用 50ms 截止；同步调用返回后撤销该会话。候选点击由窗口过程投递私有消息后请求 `TF_ES_ASYNCDONTCARE`，同一时刻最多一个待执行点击会话；会话开始时核对焦点代次、本地展示编号和组合文本未变，再发 `Select`，50ms 预算从会话开始计算。结果只在会话内取得并写入，不存在迟到提交。`OnTestKeyDown` 不发输入请求，只按上次状态本地判定；判定吃掉的键必须是引擎在该状态下必处理的子集，由测试穷举核对。真实宿主实测（Notepad++）表明预判吃下、处理时放行的原键不会交还应用，因此预判前必须确认后台可用：已有连接以非阻塞检查复用，否则在 50ms 期限内只做连接握手，连不上即不吃键。宿主终止组合时只做标记，下一按键会话先发 `Clear`。判定规则为 contracts 的 `InputState::consumes`，引擎测试在全部可达状态下核对其与 `handled` 完全一致；`OnKeyDown` 同样先按此判定，不被吃的键不发 IPC。

文档焦点变化（`ITfThreadMgrEventSink::OnSetFocus` 或按键上下文更换）不发 IPC：旧编辑器失效并取消自有组合（同步锁被拒时排队一次只删一致自有组合的异步取消），下一按键会话先发 `Focus`。后台以 `NotFocused`/`StaleFocus` 拒绝按键（另一宿主已取得焦点）时，被拒的键未被处理，同一截止时间内重新报告焦点后补发一次，不算重放；再次被拒即作废连接、放行原键。

按键映射：Alt/AltGr 组合一律放行；Ctrl 只认 `Ctrl+.`（中英标点）与组合中的 `Ctrl+L`（学习信息），其余 Ctrl 快捷键放行；单击 Shift（期间无其他键、无 Ctrl/Alt）切换中英；上/左为前一候选、下/右为后一候选；字符按当前布局以 `ToUnicodeEx` 不改变键盘状态取得，死键与多字符放行。TSF 只把按键交给键盘开闭状态（`GUID_COMPARTMENT_KEYBOARD_OPENCLOSE`）为“开”的 TIP，新线程管理器初值为空即关闭；TIP 激活时打开它，并在激活期间监听，被宿主或开关热键关闭即重新打开，中英文只由本输入法自己的状态切换，停用后不再干预。

编辑组件只替换自有组合、空插入点或用户选区，先核对原组合文本与光标。用户选中文字后输入，新组合（或无组合时的直接提交）替换选区，同系统输入法：后台无结论时尚未写入，原键交宿主按原样替换；组合写入后取消或故障撤回只删除组合，被替换的选区不恢复，与宿主处理原键的结果一致。只读上下文在 `OnTestKeyDown` 预判时即放行（`GetStatus` 无需编辑锁），编辑会话内仍复验，且都在调用后台前判定，后台状态因此不变；预判吃下的键不得因会话可预见的拒绝而放行。后台在预判时已断开则先撤回自有组合、收起候选，再放行原键。外部改写或光标移出旧组合时只结束旧组合、不改正文，后台先 `Clear` 后按当前插入点处理本键。后台结果只在本会话内取得，不存在旧快照写入。已确认的提交单独报告，后续清理失败也不得重放或删除已提交前缀。

候选窗按微软 IME 要求在宿主进程内创建：TSF 线程惰性创建、停用时销毁，以 `ITfContextView::GetWnd`（失败时用 `GetFocus`）作 owner，与宿主处于同一 z-order 层级；窗口类用 DLL 模块句柄注册。不用标准按钮，改为自绘与命中测试，避免同线程控件取得焦点、激活弹窗并终止组合。显示、隐藏和移动时发 `EVENT_OBJECT_IME_SHOW/HIDE/CHANGE`；UIA 遵循 IME 约定：AutomationId 为 `IME_Candidate_Window`，显隐发 MenuOpened/MenuClosed，选中项发选中事件，Name 为候选字。候选窗创建时仅临时把 TSF 线程切到逐显示器 DPI 感知，随后恢复宿主上下文，防止系统按位图缩放候选文字；仍使用宿主同一上下文的 `GetTextExt` 坐标。候选数据取自按键回复的 `InputState`，不另走 IPC；快照更新时递增本地展示编号、取消旧鼠标捕获，并在显示后同步处理一次 `WM_PAINT`，避免先出现空边框再补画内容。

候选窗实现细节（B2）：组合矩形在按键/点击会话写入后以同一 cookie 的 `GetTextExt` 取得（全零矩形视为宿主不知道），位置逐级退：整段组合 → 组合起点（折叠范围，部分宿主只给得出插入点）→ 本线程 `GetGUIThreadInfo` 光标 → 候选窗正在显示时的原位置 → 本输入框（编辑器）上次取得的组合矩形 → 输入区域（`ITfContextView::GetScreenExt`，取不到则视图窗口或焦点窗口的屏幕矩形），区域作为整体矩形交给同一摆放规则，候选窗贴其外沿、不盖住输入区，区域高过屏幕时夹到工作区边角；全都没有才暂不显示。退路位置只用于按键会话，布局通知只按真实矩形移动；有候选且处于组合时显示，否则隐藏（空码时编码只留在组合下划线里）。Chromium 系宿主（Chrome、Electron、WebView2）的组合矩形由渲染进程异步回报，组合开始或改动后的同一会话里常返回 `TS_E_NOLAYOUT` 或旧光标位置，随后才以布局变化通知补来；因此每个编辑器在其上下文登记 `ITfTextLayoutSink`（随编辑器释放注销），组合中且有候选时收到 `TF_LC_CREATE/CHANGE` 即请求只读编辑会话（`TF_ES_READ | TF_ES_ASYNCDONTCARE`），核对自有组合未被改写后重取矩形，显示或移动候选窗；同一快照只移动位置，不递增展示编号、不作废待执行点击，位置未变则不重绘。窗口过程只按句柄在本线程登记表中以弱引用找回候选窗，不在窗口数据里存业务指针。按下与抬起落在同一行才投递私有点击消息（展示编号 + 页内序号）；同一展示最多受理一个待执行点击，展示更新或会话结束即解除。点击会话核对组合文本未被改写（不要求光标在末端），不结束旧组合、不请求清空；宿主已终止组合时拒绝并把清空留给下一按键。UIA 根元素与候选项以 COM 线程模型声明，候选项运行时编号含展示编号，展示更新后旧元素报告不可用；HelpText 为编码提示；UIA 的选择操作被拒绝，选字只经编辑会话。只有 UIA 客户端监听时才构造元素发事件。产品要求界面不得出现任何蓝色：候选窗取选项中的主题配色，不用系统强调色或选中色，仅在用户开启高对比度时改用其系统颜色。外观（10-23 重设计）：高亮行为圆角底色加左侧指示条，注释列对齐，页脚（仅可翻页或拼音反查时出现）以分隔线隔开；纯 GDI，内存位图双缓冲、库存 DC 画刷改色，字体按 DPI 与候选字体缓存并核对实际字体名回退；Win11 由 DWM 画圆角与主题色边框，Win10 退回直角自绘外框。宿主终止组合时立即收起候选窗；外观数据不经 DLL 读盘。

会话交换结论分三种：未发出或后台明确未处理（旧快照、焦点被夺）为“跳过”，不写入、不作废；结果不确定为“丢失”，同一会话撤回仍一致的自有组合并放行原键；其余为“写入”。写入阶段失败同样在会话内撤回自有组合，下次按键先 `Clear`。停用时显式断开管道，不依赖其余引用何时释放。

队列、查询和结果页有界；TSF 单次主动等待总预算 50ms，连接/编码/接收共享绝对截止时间。故障不重放、不交付迟到提交；不持锁阻塞、不逐键建线程或记录输入。

DLL 传输的首版安全策略采用显式进程期驻留：默认 `Runtime::new` 仍拒绝 DLL，专用入口 `new_process_resident` 在激活阶段用系统 PIN 固定完成回调所在模块，不支持热卸载。停止先取消/释放管道和取消令牌，再以绝对期限调用 `shutdown` 关闭准入并等待资源所有权排空；超时保留关闭状态和仍存活的资源，可再次等待。排空不等于完成线程已返回，回调尾部仍由模块 PIN 保护；不得在 DllMain 或输入回调创建/排空运行时。未来 TSF 必须按此驻留策略报告不可热卸载；安装/升级不得将关闭成功当作 DLL 已从宿主卸载。每个宿主进程一个进程期驻留 `Runtime`，由首次激活创建，供各 TIP 线程的连接共用；它是传输基础设施而非业务状态，各线程的连接与会话状态仍归各自 TIP 实例。

## 数据与配置
- Rust 工具只解析锁定单字表、tigress 词码、常用字集、拼音单字/读音、拆分和简繁映射；不导入小狼毫外观配置（候选窗配色与字体由设置给出）。复用数据不是兼容运行时。
- 码表不转换成 JSON 或其他中间数据包：所需 9 项原文（取自虎码官网盘的“虎码秃版 小狼毫（Win）”方案包）以原始字节随仓库存于 `resources/tiger`（`.gitattributes` 禁止换行转换，治理测试核对已入库且为 `-text`），锁定清单 `resources/tiger.lock.json` 编译进程序；后台、命令行与打包驱动每次加载都按清单核对路径、大小与 SHA256 后只解析所需数据段，任一不符即拒绝。原件只读。
- 启动校验并构建排序索引，二分查询；输入时不读文件或扫描整表。不引入数据库、自定义二进制格式。
- 保留多编码/多音字/多拆分码，完整码与实际码交叉检查，不仅凭长度判断全码。
- 独立 APPDATA，复用目录占用、链接拒绝、配置事务替换；不导入个人 Rime 数据。安装版后台与查字窗使用程序目录下的 `tiger` 码表目录与 `%APPDATA%\TigerType`（不存在则新建，已有目录须带所有权标记）；开发期 `serve <码表目录> <数据目录>` 仍可指定独立目录。
- 安装包由 Inno Setup 6.7 编译（用户批准的唯一非 Rust 工具；`.iss` 只含声明与停后台、登记/改名/清理占用旧文件的少量 Pascal），Rust 打包驱动 `--example package` 先构建 release、校验码表/字体/语言文件（均在仓库内，换机克隆即可打包），并核对脚本逐个列出的字体与码表和清单一致（码表须装到 `{app}\tiger` 并保持相对路径）；安装时删除旧版的 `tiger-v1.json`。两种 MSVC 目标静态链接 CRT。安装需管理员，固定装到 Program Files（不提供改目录）；先放程序再分别以 64/32 位注册 DLL；字体全机安装；HKLM Run 登记 `serve` 使各用户登录时以普通权限启动自己的后台，安装结束以原用户身份启动一次；开始菜单只有“查字与设置”；不添加或切换键盘。`tigertype.exe` 为 GUI 子系统，从终端运行时借用父控制台，无控制台时 `serve`/`lookup-window` 失败弹错误框。升级先以原用户身份 `stop`（停止确认后等旧后台进程退出才返回）；DLL 驻留且协议严格相等，宿主不重开只能出英文，因此启用重启管理器：现名文件与历次改名的 `*.old` 一并登记检测，准备页列出占用程序，经用户同意关闭并在装完后重启支持重启的程序；不关或关不掉的，在关闭步骤之后（`BeforeInstall`）把仍被占用的旧程序与 DLL 改名并登记重启后删除，装完删除已无人使用的 `*.old`。`*.old` 不得列入 `[InstallDelete]`：它们已在重启删除队列中，Inno 会据此要求先重启；卸载先请求停止后台、注销 DLL、删除程序与自启项，占用文件重启后删除，保留用户数据。
- TIP DLL 与后台程序须位于 Program Files，或位于已对 ALL APPLICATION PACKAGES 授予读取/执行的独立目录，否则 AppContainer 宿主无法加载；DLL 不读取数据文件。
- 注册入口为 DLL 导出的 `DllRegisterServer`/`DllUnregisterServer`（regsvr32，须管理员）：COM 类写入 HKLM\SOFTWARE\Classes（`InprocServer32`、`ThreadingModel=Apartment`），以 `ITfInputProcessorProfileMgr` 登记简体中文（0x0804）语言配置（默认启用，图标为 DLL 同目录的 `tigertype.ico`，缺图标拒绝注册；任务栏据此显示虎码图标，不再退回语言名“简体”），以 `ITfCategoryMgr` 登记键盘 TIP、沉浸式与托盘三类别；注册前要求 DLL 为绝对路径且同目录有后台程序，任一步失败回滚；注销尽力移除全部内容，重复注销时系统对未登记项的报错照实返回。x64/x86 DLL 放同一目录（x86 改名）共用一个后台，分别由 System32 与 SysWOW64 的 regsvr32 注册；32 位 COM 类经 WOW64 写入 32 位视图。注册测试只核对注册内容，并在临时私有配置单元（`RegLoadAppKeyW`）中验证读写，不写系统或用户注册表。

## 工程治理

4. 先完成 IPC DLL 回调驻留/关闭，再接 TSF/混合位数/多宿主；不得直接移除 EXE 限制。按三批推进：A 传输与认证（安全描述符、双侧认证、删除通知通道与后台候选窗、懒连接与槽位回收、协议 v5）；B 最小 TIP 与宿主内候选窗，分两步：B1 类工厂、按键/焦点 sink、按键映射与本地判定、统一按键编辑会话（协议 v6）；B2 宿主内候选窗、UIA/WinEvent、点击异步会话，删除候选预览与 ui 候选窗；C 先实现注册/注销入口，再经授权在暂存目录注册后做真实宿主验收，验收后注销。

验收覆盖：简/全码、稳定顺序、两种四码模式、空码/翻页/退格/清屏、非 BMP；多音字、ü/v、多编码、缺资料、简繁一对多与去重、实际字形与码对应；查询不改变会话；超时/卡死/断连/迟到/旧快照不重复上屏；坏包/配置失败/路径攻击保留旧数据；故意架构违规失败。
