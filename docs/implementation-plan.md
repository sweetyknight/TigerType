# TigerRime 实施方案：低占用、清晰边界与可维护架构

## 一、目标与交付范围

使用 Rust 重写 Windows 输入法前端，保留 librime；完整支持当前虎码包在 Windows 上实际可用的功能。

- 支持 Windows 10/11 x64，以及系统中的 32 位应用。
- 面向个人使用，与小狼毫并存，独立注册、独立数据目录，不覆盖旧配置。
- 保留当前候选窗风格，增加常用功能的可视化设置。
- 不扩展为通用输入法平台，不重写 Rime 算法，不引入云服务、遥测或自动更新。
- 低资源占用、故障不拖住应用、模块可独立测试，均作为交付条件，而非后续优化事项。

开发目录为 D:\Projects\TigerRime。解除规划模式后，首先将本方案保存为 D:\Projects\TigerRime\docs\implementation-plan.md。

## 二、架构与模块边界

### 进程结构

应用进程内的 Rust TSF DLL（x64/x86）通过有截止时间的 IPC 连接 Rust 前端管理进程；管理进程负责候选窗、状态通知、会话及请求调度和引擎生命周期。管理进程通过有界消息队列与 IPC 连接独立引擎进程，后者加载 librime、Lua、OpenCC。

每个 Windows 登录会话只运行一套管理进程和引擎进程，不为每个应用启动引擎。设置与部署按需运行、完成退出，不新增常驻看门狗进程。

管理、引擎、设置和部署使用同一可执行文件的不同启动模式，但只初始化当前模式需要的资源。引擎动态库只在引擎和部署模式加载，不能进入宿主应用或设置界面进程。

### 代码组织

采用 Cargo workspace，按真实依赖和测试边界划分六个 crate，不按每个功能开关继续拆分：

| 模块 | 负责 | 明确禁止 |
|---|---|---|
| contracts | 请求、响应、输入状态、错误类型及协议版本 | 依赖 Windows、librime、界面或文件系统 |
| ipc | 管道连接、消息编解码、身份检查、截止时间和取消 | 候选计算、界面操作、业务重试决策 |
| engine | librime C 接口、会话、候选和配置调用 | 操作窗口、托盘、TSF，直接管理客户端连接 |
| tsf | COM/TSF 接入、按键、组合文本、上屏和无障碍接口 | 加载词库、运行 Lua、绘制候选窗、部署配置 |
| ui | 候选窗和原生设置控件 | 直接调用 librime、修改词典、决定故障恢复 |
| app | 组装模块、运行模式、会话调度、恢复与配置部署流程 | 重复实现引擎算法或底层通信 |

app 内使用普通模块区分配置、部署、监督和设置控制器，不额外制造框架或插件系统。

依赖方向固定：基础契约 → 通信或引擎适配 → 接入与应用组装。模块间不得通过全局可变状态、窗口句柄或裸指针暗中耦合。

### 接口与所有权

- IPC 使用带版本和长度限制的消息；包含会话、请求序号及引擎代次，用于拒绝迟到和过期回复。
- 跨模块传递拥有明确所有权的数据，不传播 Rime 指针、COM 对象或借用中的引擎内存。
- 所有 Rime 调用由引擎进程内的专用线程串行执行；界面状态归界面线程所有。
- UI 接收状态快照并输出用户操作，不主动查询引擎；界面只访问设置控制接口，不直接写文件。
- Windows/FFI 的 unsafe 集中在边界，配对释放资源，阻止 panic 穿过系统回调。
- 不为每个对象增加 trait、工厂和包装层；只有需要替换依赖进行故障测试的边界才抽象。

## 三、低占用与可靠性约束

### 输入路径

- 使用事件驱动、可取消的管道 I/O，不忙轮询，不无限等待，不在持锁期间进行阻塞通信。
- 单次输入回调的主动等待总预算为 50ms，连接和重试共用预算。
- 输入路径不部署、不遍历目录、不读取配置文件、不同步启动外部程序、不输出逐键日志。
- 请求队列有界；光标位置等可合并更新只保留最新状态，按键和上屏事件不得静默丢弃。
- 不按按键、客户端连接或候选项创建线程；自有后台线程数量固定，Rime 内部线程单独监测。

### 故障处理

按已确认的取舍，优先保证应用不被拖住：

- 超时或引擎崩溃后取消当前未上屏输入，暂时放行原始按键。
- 不修改已上屏文字，不重放状态不确定的按键，不接受旧引擎的迟到提交。
- 管理进程负责终止异常引擎和恢复，每分钟最多自动重启三次，超过后提示手动处理。
- 客户端退出、断连和异常终止均释放对应会话。
- 管道按用户及登录会话隔离，验证消息边界和客户端身份。
- 引擎放入 Windows Job Object 管理生命周期与资源保护；内存保护预算以完整功能基准峰值的两倍设定，最低 256MiB，部署进程单独测定。触发限制走统一故障恢复流程。

### 界面与缓存

- 使用原生 Windows 控件、DirectWrite 和原生绘图，不引入 Electron 或 WebView。
- 候选窗隐藏时停止绘制；不使用持续动画或周期性刷新。
- 字体、布局和绘图资源按需复用，缓存有容量边界，并在主题、DPI 或设备变化时正确失效。
- 不重复传输整份主题、词库或历史状态；仅传输当前候选页及必要状态。
- 设置界面关闭后释放资源；日志采用滚动大小限制，默认不采集输入内容。

## 四、虎码功能、设置与数据保护

### 功能基线

使用当前提供的虎码包，固定资源版本和校验值，保留：

- 虎码单字、虎码词组、拼音++、英文补全及拼音和笔画反查。
- 当前选重、翻页、清屏、中英文切换、重复上屏与方案快捷键。
- 常用字过滤、拆分与拼音注释、Unicode 提示、简繁转换、Emoji 和符号。
- 日期时间、数字大写、计算器和网址快捷指令。

保持现有候选顺序及学习开关，不擅自给虎码开启动态调频。不启用已注释的扩展，不开发手机端键盘选项。

引擎固定使用官方 librime 1.17.0 Windows MSVC x64 发行构建，锁定校验值，检查必要接口及 Lua 模块；补齐基础配置和部署依赖。

允许对内置 Lua 做安全改造：限制危险调用、异常计算量和错误传播；保留正常用途。网址启动移出同步按键路径。特殊字体优先使用本机已有字体，缺失时提示，不擅自下载安装。

### 可视化设置与配置归属

设置页面包括：

- 默认方案、候选数量、横竖排和内联编码。
- 主文字、注释与序号的字体字号。
- 内置主题和主要颜色。
- 方案开关、方案切换及常用选重快捷键。
- 重新部署、打开配置目录、恢复默认和诊断状态。

保留高级 YAML 编辑，优先级固定为：手工覆盖 > 图形设置 > 内置默认。

图形设置只写受管补丁，不整份重写个人 YAML；被手工覆盖的设置明确显示原因。

使用独立的 %APPDATA%\TigerRime 数据目录，不共享小狼毫正在使用的用户词典数据库。部署先在临时目录验证，通过后协调引擎关闭并切换；失败继续使用上一份配置。卸载默认保留个人数据。

## 五、实施步骤与验收

### 实施顺序

1. 保存方案、建立基线：固定依赖与虎码资源，整理功能样例，采集原程序和独立引擎的延迟、内存、CPU、句柄及线程数据。
2. 打通最小稳定链路：完成模块骨架、引擎隔离、IPC、x64/x86 TSF 与候选窗；先通过故障注入，再扩展界面。
3. 完成虎码与设置：补齐功能、原生样式、Lua 安全改造、可视化设置及可回退部署。
4. 安装与长期试用：验证独立安装、注册、升级、卸载和回退，保留原输入法作为备用。

每阶段都交付对应测试，不在最后集中补测试。新增和修改代码添加适当、简短的简体中文注释。

### 验收门槛

- 架构：无循环依赖；TSF 不依赖引擎或界面模块；业务逻辑可使用模拟引擎、故障管道进行独立测试。
- 功能：虎码清单全部通过，覆盖候选顺序、组合文本、非 BMP 汉字、Emoji、字体回退及多屏 DPI。
- 应用：覆盖浏览器、微信/QQ、Office/WPS、VS Code、终端，以及 32 位和管理员权限程序。
- 延迟：在用户机器上，预热后普通输入链路以 P95 ≤10ms、P99 ≤25ms 为目标，明确测量起止点；自身通信等待不能突破既定预算。
- 空闲占用：非部署、非设置操作期间，十分钟平均 CPU 目标不超过整机总算力的 0.1%，无持续绘制或高频轮询。
- 资源稳定性：至少两小时会话反复创建销毁和八小时日常测试；会话、线程与句柄能回收，内存回到预热后的稳定区间，不随操作次数持续增长。统计两个后台进程及宿主 TSF 增量，不能把占用转移后称作优化。
- 异常与数据：验证卡死、崩溃、断连、迟到回复、资源超限和部署失败；不得重复上屏、破坏原配置或损坏用户词典。

当前仅完成方案修订，尚未写入文件、修改代码或执行性能测试。
低占用以实测门槛验收，不承诺未经验证的降幅；引擎故障时仍可能需要重打当前未上屏编码。
