## Windows 已定位的结论

- **连续输入错位（已修）**：`Popup::show` 读 DPI 时先把窗口移到未夹取的组合位置，候选窗要翻到光标上方或靠右夹取时每次更新都经过错误位置。同一 Edge 底部场景，错误位置采样由 70/217 降为 0，单键多次移动由 60/106 降为 0（满载 1/141）。
- **候选窗白框（已修）**：DWM 描边跟窗口几何走，内容晚一帧，首显时屏幕上是空心描边，通常一帧 4ms、最长 15ms；Claude 244 次首显有 237 次经过这一帧。帧探针看不到，靠回溯录屏逐帧实证。现由 `UpdateLayeredWindow` 一次交付位图与尺寸、圆角描边自绘，位置仍走 `SetWindowPos`（DPI 不感知宿主要求）。Edge 深浅页面与 DPI 不感知编辑框共 40 次首显空框 0 次，首帧完整；用户重开 Claude、ChatGPT、Chrome 后确认消失。这类宿主里候选窗偏大 1.5 倍的问题同时修复。旧版在浅色背景上是否有阴影未能对比。
- **字体重复（已修）**：私有加载让每个宿主在 COM 构造时流式读 26MB 字体（约 32ms）且与系统字体重复，已删除，Windows 只用系统字体，后台启动时核对文楷与字根。安装器改为全机或当前用户已有就跳过。
- **开始菜单搜索看不到候选（已修）**：SearchHost 是 AppContainer 沉浸式进程，连接、按键、同步编辑会话和组合一直正常，空格能上屏；框里的编码是组合文本，本 TIP 不提供显示属性、`RichEditBox` 不画下划线，所以看着像原键。旧版候选窗先无 owner 创建，被放进 band 15 并由 Shell 隐去（`DWM_CLOAKED_SHELL`），事后 `SetWindowLongPtrW(GWLP_HWNDPARENT)` 报错 87 且返回值没人看。现改为创建时就以视图窗口（取不到时焦点窗口）为 owner，宿主窗口变了就收起旧窗口、换新窗口，不再事后改 owner。正式安装后候选窗与搜索窗同在 band 6、未隐去，屏幕帧可见。系统设置搜索框不是 AppContainer，修复前后都正常。
- **“不出现”与“卡”未复现**：12–33 键/秒、含 rollover 与 16 线程满载，在 Typora、记事本、Notepad++、Edge 约 20 轮，候选窗未在组合中消失，无丢码或残留字母。白框修复后用户确认延迟消失，“不出现”未单独确认。

本机单块 4K、150% 缩放，RTX 5070 Ti、240Hz；排除了坐标虚拟化和长驻宿主 GDI/USER 泄漏。VS Code 隔离实例未能启动，未测。

## Mac 已定位的结论

本机为 macOS 26.6（25G72）/ARM64、Command Line Tools，Kaiti SC 不可用。只带链接器签名的包能被系统发现、加载并正常输入；码表全部 103,460 个单字由随包字体覆盖。

- **系统发现**：包标识须含独立的 `.inputmethod.` 段，旧标识以 inputmethod 结尾时系统发现不到；已改为 `local.inputmethod.tigertype`。
- **启动崩溃**：IMKServer 是系统类簇，不能继承；改为主线程持有系统实例，依赖以强关联传给控制器。
- **有下划线编码、无候选**：初始化 client 与激活 sender 是不同代理对象，旧逻辑按指针拒绝；改为激活时校验并绑定本次文本对象。
- **系统菜单无反应**：IMK 直接把命令字典发给菜单 action，控制器须实现 `invoke:`。
- **Codex 只能输入第一个码**：Chromium 的标记范围同步更新、文档缓存异步更新，子串比较失败导致每键重置组合；改为只按绑定客户端的标记范围、UTF-16 长度与代次判断。
- **上屏缺字**：上屏后由宿主绘制，进程私有字体无效；安装器把全部字体发布到 `/Library/Fonts`。用户确认“𤛭、𨰻、𪚥”可显示，不推广到所有宿主。
- **生僻字方框**：文楷缺 72,406 个码表单字，天珩 P0/P2/P1 分别补齐 104/59,209/13,093 个。
- **单击 Shift 不切换**：IMK 把每个修饰键事件投递两次，旧判定把同一 Shift 的第二次按下当成“期间有其他键”；用户确认恢复。
- **菜单栏图标偏低**：PNG 被 AppKit 按 36 点加载，改为 16 点逻辑尺寸；实际对齐待安装后复核，系统缓存旧图时可能须注销重登。
- **11-01 修复（原生测试通过，11-03 已安装）**：输入法只用系统字体，不再把约 90MB 字体读入内存私有注册；安装按字族判重，跳过前实际解码已有字体，拒绝损坏文件及缺字根的文楷；候选窗内容画完才显示；组合写入后有界补查两次坐标，查询期间失焦或结束组合时不再复活旧候选；宿主不给坐标时退到鼠标位置。Chromium 在 Mac 上给旧坐标是由 Windows 现象推断的。
- **11-03 优化前资源快照**：18:22 安装的进程启动约 11–18 分钟后，系统计费内存（physical footprint，含压缩/换出页）约 38–39MiB，进程历史峰值 149.5MiB；RSS 随回收为 64–75MiB，不能与独占计费内存混算。堆有效分配约 24.4MiB，分配器碎片/保留页约 7.2MiB，其余为系统私有页、图形、元数据与栈。复用同版 Release 引擎、只读安装包码表的独立探针测得常驻字典请求 16.6MiB/20 个堆块；读入原文 32.6MiB，解析后合计 80.5MiB，建表时请求峰值 104.5MiB、计费峰值 141.4MiB，加载约 0.31 秒（含计数开销，不是输入法启动就绪耗时）。原文与解析中间数据释放，字典析构后堆请求回到基线；分配器页回收仍有延后。两次 30 秒观测中，一次 top CPU 全为 0.0%，另一次精确计数累计 CPU 2.98ms（约单核 0.01%）、磁盘读写增量 0、包空闲唤醒 0、interrupt 唤醒 1；线程 5–7 个，采样中引擎/工作线程均阻塞等待。未测持续输入负载或长期增长，不能据此完成资源验收。

## 未解决问题与已知限制

**候选窗**

- 开始菜单搜索等 `RichEditBox` 宿主里组合没有下划线（本 TIP 不提供显示属性），编码看着像已输入的字母。
- 位置滞后（未修）：Chromium 系宿主首显给旧坐标，候选窗先在旧位置出现，布局通知到达后才纠正，通常差一个字宽、6–38ms，换行时差一整行（实测 769px）。Claude 194 次首显移动 11 次，ChatGPT 94 次移动 12 次（含 2 次上下翻转），Chrome 17 次移动 1 次。修复需要首显等待布局通知，有时延代价，是否修待定。Edge 页面主线程繁忙时宿主迟到的旧坐标也会把候选窗拉回一到几个字。
- 从不给位置、不发布局通知又无系统光标的宿主，候选窗退到上次组合位置或输入区域外沿，只是近似位置；连窗口都取不到时不显示。
- 微信候选不显示/空框残留：10-27 的生命周期修复之后未在微信复测，现用构建也未测，不能和白框问题合并为同一根因。
- 宿主若始终不执行排队的点击会话，同一展示的后续点击被挡住，直到下一次展示更新。
- 组合中经菜单切换全角或标点后，候选窗仍是切换前的快照，鼠标点选因编号过期被拒绝，继续打字即恢复。
- 高负载 x86 尾部波动原因未定位。

**输入与宿主**

- 单击 Shift 判定不感知鼠标：Shift+鼠标选择后松开会切换中英。
- 词模式的词候选不显示拆分与编码（官方逐字显示），转换字形的词不标注来源；单字候选与拼音反查正常显示。
- 查字词读音：不在官方 PYPhrases 里的词靠单字读音拼合，轻声给不出，多音字只差声调时取单字表首个读音，会错（如“几个”给 jī gè）。
- 拼音查词只认全拼连写的完整串，没有简拼和前缀补全；词表 130,441 个词里有 16,423 个官方拼音表没有（如“不可能、出门、叫做、二十”），拼音查不到，用查字窗粘贴文字可查词码。
- 后台回收或重启后新会话恢复中文与半角；组合中按 Home/End/Delete 等未映射键交给应用，下一键按外部改写处理。
- DLL 进程期驻留且协议严格相等：升级时未关闭的程序仍载旧 DLL，只能放行原键（只出英文）直到重开，连接失败时无提示。安装准备页可代为关闭，但本机实测 12 个占用程序中只有资源管理器与 Codex 支持自动重开。
- 微软输入法候选框消失：两次取证均为 TextInputHost 主线程卡在 EdgeHTML 的 `PeekMessage(WM_PAINT)` 忙等，重启 TextInputHost 即恢复；都紧跟电脑操控会话开始，TigerType DLL 不在 TextInputHost 中，未发现两者通道。
- 放开低完整性后同会话沙箱进程都能连接占槽，回收只能缓解拒绝服务；后台须以非提升权限运行。管道关闭超时不等于资源已释放。

**界面**
